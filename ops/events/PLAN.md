# 회원가입 이벤트·혜택 운영 계획 (2026-11-02)

세준 지시: 회원가입 이벤트·혜택 구상 → 다른 플랫폼 참고 → 검토 → 전체 업데이트 → 세준 확인.

## 1. 법·세무 검토 (원문 확인한 것만, 링크)

### 1-1. 경품 소득세 — 1인 1회 5만 원 이하로 운영 → 원천징수·주민등록번호 불필요
- 소득세법 제84조 제3호: 기타소득금액이 "건별로 5만원 이하인 경우" 소득세를 과세하지 않음(과세최저한). 건별 판단은 "기타소득의 발생근거, 지급사유 등을 고려하여 거래건별로" (소득세 집행기준 84-0-1). 넘으면 22%(국세 20% + 지방 2%) 원천징수(소득세법 제129조 제1항 제6호) — 그때는 실명·주민등록번호가 필요해짐. 근거: [taxly 기타소득 원천징수 기준](https://taxly.kr/qna/16289-%EA%B8%B0%ED%83%80%EC%86%8C%EB%93%9D%EC%9D%98-%EC%9B%90%EC%B2%9C%EC%A7%95%EC%88%98-%EA%B8%B0%EC%A4%80)
- 결정: 1인 경품 20 USDT 상당, **지급 시점 원화 가치 5만 원 이하**를 규칙으로 못 박음(`ev_events.prize_krw_cap = 50000`, 지급 시 `ev_claims.krw_value` 기록). USDT가 2,500원을 넘으면 수량을 줄인다. 같은 계정 90일 내 재당첨 제외(건별 쪼개기 오해 방지).
- 비교: 빗썸 텔레그램 이벤트는 아이폰 경품 "제세공과금은 본인 부담" — 고가 경품이라 원천징수 대상이 된 사례. [스마트투데이](https://www.smarttoday.co.kr/ko-kr/articles/89545)
- **세무사 확인 필요(세준 결정 1):** ① 과세최저한 경품의 지급명세서 제출 의무 여부, ② 경품 비용의 장부 처리(광고선전비), ③ 비거주자(Perpline) 경품: 국내원천 기타소득 22% 원천징수가 원칙이고 조세조약 제한세율 적용 여부는 전문가 답변이 엇갈림, 원천징수세액 1천 원 미만이면 면제(소득세법 시행령 제216조의2 제1항 제7호로 소개됨) — 20 USDT 는 면제선을 넘는다. 근거: [taxly 비거주자 경품](https://taxly.kr/qna/140299-외국인비거주자에게-경품-지급-시-기타소득-원천세신고-필요-자료는). 그래서 **Perpline 추첨은 세무사 답을 받기 전까지 켜지 않는다.** 규칙 페이지에는 "한국 법상 신고·원천징수가 필요하면 실명·ID 번호를 요청할 수 있다"고 적어 둠.

### 1-2. 가상자산 관련 법 — 자기 코인을 소액 증정하는 것은 가상자산사업자 영업이 아님(판단)
- 특금법 제2조 제1호 하목: 가상자산사업자 = 매도·매수·교환·이전·보관·관리·중개 등을 "영업으로 하는 자". 대법원(2024도10710)은 '영업으로' = 영리 목적의 계속·반복, 불특정 다수를 위해 거래를 대행하고 대가를 받으면 사업자, 자기 이익을 위해 거래소만 쓰는 이용자는 원칙적으로 아님. [nepla 해설](https://www.nepla.ai/wiki/금융-투자-외국환/핀테크-가상자산/-일문일답-오로지-자기의-이익을-위하여-가상자산거래소를-통해서만-가상자산의-매매나-교환을-계속·반복하는-가상자산거래소의-일반적인-이용자가-가상자산사업자에-해당하는지-ov59rp5d3n06)
- 판단: 체인브리프가 자기 계정의 코인을 월 10건 홍보 경품으로 보내는 것은 고객을 위한 대행·보관이 아니므로 사업자 신고 대상으로 보기 어렵다. 다만 ① 고객 코인을 받아 두거나 대신 사고팔지 않는다, ② 경품은 등록된 국내 거래소(업비트·빗썸) 계정에서 출금한다, ③ 특정 코인 매수·거래를 응모 조건으로 걸지 않는다(가상자산이용자보호법상 불공정거래 오해 방지).
- 트래블룰: 2022-03-25 시행, 100만 원 이상 이전 시 송·수신인 정보. 업비트(2025-02-13)·빗썸(2025-04-01)은 100만 원 미만도 미등록 주소 출금 제한 → 받는 사람 주소를 출금 주소로 미리 등록해야 하고, 개인지갑·화이트리스트 거래소도 등록 필요, 미신고 해외거래소(쿠코인·멕스씨 등 23곳)는 등록·출금 불가. [스마트투데이](https://www.smarttoday.co.kr/ko-kr/articles/72890)
- 결정: **지갑 주소는 응모 때 받지 않고 당첨자에게만** 받는다(최소 수집). 수령 신청 항목 = 코인·네트워크·주소·받는 거래소·수령인 실명(주소 등록용). 미신고 거래소 주소는 지급 불가로 안내.

### 1-3. 표시·광고, 사행성 — 무료 응모 + 핵심 조건 모두 표시
- 소비자 현상경품 한도(단일 2,000만 원·예상매출 3%)를 정한 공정위 경품고시는 2016-05-30 폐지 행정예고(기사 제목 "경품 규제, 35년만에 완전 폐지"; 확정 공포일은 원문에서 확인 못 함 — 어느 쪽이든 우리 경품 규모는 옛 한도에 한참 못 미침). [KDI 경제정보센터](https://eiec.kdi.re.kr/policy/materialView.do?num=154699), [시사경제 기사](https://www.sateconomy.co.kr/news/view/179588199800745). 금액 한도는 없지만 표시광고법상 거짓·과장·기만 광고 금지는 그대로 → 규칙 페이지에 응모 기간·자격·당첨 인원·경품(코인 종류·수량 기준)·추첨 방식·발표·수령 기한·세금·개인정보·문의를 모두 적었다.
- 사행성(판단): 참가자가 돈·재물을 내지 않는 무료 응모라서 사행행위로 볼 요소가 없도록 구성 — 구매·입금·거래·공유·마케팅 동의 모두 조건 아님, 1인 1회, 당첨 확률 동일.
- 해외(Perpline): 캐나다는 유료 응모 게임을 형사 문제로 보고 당첨자에게 수학 문제를 두는 관행, 퀘벡은 프랑스어 자료 필요, 브라질은 재무부 사전 승인(현지 법인만) → 브라질 제외, 캐나다는 수령 때 수학 문제, 퀘벡 제외. 필리핀은 500페소 넘는 경품 등기우편 통지 → 목록에서 뺌. [ABA Business Law Today 2025-06](https://www.americanbar.org/groups/business_law/resources/business-law-today/2025-june/what-legal-teams-need-know-about-global-sweepstakes-promotions). 응모 폼은 **허용 국가 목록(allow-list)** 방식, 서버도 `ev_events.allowed` 로 강제. 한국·미국은 Perpline 서비스 대상이 아니므로 제외(사이트 기존 고지와 동일).

### 1-4. 개인정보·마케팅 동의
- 개인정보보호법 제15조 제2항: 동의 받을 때 ① 목적 ② 항목 ③ 보유·이용 기간 ④ 거부 권리와 불이익 고지. [법률위키](https://korea.legal/wiki/%ea%b0%9c%ec%9d%b8%ec%a0%95%eb%b3%b4-%eb%b3%b4%ed%98%b8%eb%b2%95-%ec%a0%9c15%ec%a1%b0/) → 응모 동의 문구(아래 4) 4개 항목 + "제3자 제공 없음".
- 제22조 제1항·제7호: 동의 사항을 구분해 받고, 홍보·판매 권유 동의는 따로. 제5항: 선택 동의를 거부했다는 이유로 재화·서비스 제공 거부 금지. [IT위키](https://itwiki.kr/w/%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4_%EB%B3%B4%ED%98%B8%EB%B2%95_%EC%A0%9C22%EC%A1%B0) → **마케팅 수신은 응모 조건이 아님.** 응모 폼에 [선택] 이메일·카카오톡 체크박스(기본 해제)만, 체크한 채널만 `public.sa_set_marketing` 으로 인증 에이전트의 `marketing_consents` 원장에 기록(채널·시각·사이트·문구 버전).
- 정보통신망법 제50조: 광고성 정보는 명시적 사전 동의(1항), 21~08시 별도 동의(3항), 전송자·수신거부 방법 표시(4항), 동의 여부 정기 확인(8항). [법률위키](https://korea.legal/wiki/%ec%a0%95%eb%b3%b4%ed%86%b5%ec%8b%a0%eb%a7%9d-%ec%9d%b4%ec%9a%a9%ec%b4%89%ec%a7%84-%eb%b0%8f-%ec%a0%95%eb%b3%b4%eb%b3%b4%ed%98%b8-%eb%93%b1%ec%97%90-%ea%b4%80%ed%95%9c-%eb%b2%95-21/)
- 국외 이전: 해외 클라우드 보관은 국외 이전이지만 계약 이행에 필요하면 처리방침 공개로 갈음 가능(제28조의8 제1항 제3호, 항목·국가·시기·받는 자·목적·거부 방법 기재). [nepla 해설](https://www.nepla.ai/wiki/it-정보-방송통신/개인정보-위치정보-신용정보/-일문일답-해외-클라우드-aws-등-에서-개인정보를-보관-처리할-때-정보주체의-동의를-받아야-하는가-54gnvzpe81pr) → Supabase 프로젝트를 **서울 리전(ap-northeast-2)** 으로 만들면 이 문제 자체가 줄어든다(세준 결정 2). 다른 리전이면 각 사이트 처리방침에 국외 이전 항목 추가.

## 2. 메시지 구분 — 정보성 vs 광고성 (발송 시스템은 ops/crm/ 담당, 여기서는 만들지 않음)

| 메시지 | 성격 | 동의 필요 | 보낼 대상 |
|---|---|---|---|
| 응모 완료 화면 표시 | 정보성 | 아니오 | 응모자 본인(화면) |
| 당첨 안내·수령 방법·수령 기한 알림·지급 완료(전송 해시) | 정보성(응모한 이벤트의 경품 지급을 위한 정보) | 아니오 | 당첨자만 |
| 가입 혜택 발급 안내(쿠폰 코드·체험 기간·PDF 링크) | 정보성(회원이 신청한 혜택) | 아니오 | 신청한 회원 |
| 다음 달 이벤트 오픈, 신상품·할인, 뉴스레터, 미당첨자 "다음 기회에" + 홍보 | 광고성 | **예 (채널별)** | `marketing_consent_status` 에서 해당 채널 granted 인 사람만 |

- 근거: 수신자가 신청한 경품·사은품 지급 정보는 정보성으로 분류, 정보성 메시지에 광고가 부수적으로 섞이면 전체가 광고성이 됨. [채널톡 도움말](https://docs.channel.io/help/ko/articles/0d720440)
- 규칙: 당첨 안내 메일에 다른 상품·이벤트 홍보를 넣지 않는다(넣는 순간 광고성). 광고성은 제목에 (광고), 전송자·수신거부 방법 표시, 21~08시 발송은 `night` 동의자만. 2년 재확인은 인증 스키마의 `reconfirm_due` 사용.
- 카카오톡 채널 수신 동의는 체크만 받는다. 친구톡·알림톡 발송에 필요한 전화번호·채널 추가는 CRM 담당이 별도 수집.

## 3. 개인정보 저장 방식 — 결정: Supabase(RLS), 아티팩트 DB 아님

- 이유: 아티팩트 DB는 아티팩트를 열 수 있는 사람이 공유하는 저장소라서 응모자 이메일·지갑 주소·실명을 담기에 접근 통제가 약하다. Supabase 는 RLS 로 "본인 행만 읽기"를 강제하고, 쓰기는 security definer RPC 로만 열려 있어 1인 1회·이메일 인증·중복 차단을 서버가 보장한다. 이미 인증 에이전트가 같은 프로젝트에 회원 DB를 만든다.
- 스키마: `ops/events/schema.sql` (인증 스키마 다음에 실행). 테이블 `ev_events` `ev_entries` `ev_winners` `ev_claims` `ev_welcome`, RPC `ev_enter` `ev_my_entry` `ev_submit_claim` `ev_claim_welcome`, 관리자 RPC `ev_stats` `ev_draw` `ev_announce` `ev_purge`. 로컬 Postgres 16 + Supabase 흉내 스텁으로 실행·시나리오 테스트 완료(가입 전 응모 거부, 중복 응모·gmail 별칭·일회용 메일 거부, 비관리자 집계 거부, 추첨 시각 전 거부, 추첨, 타인 지갑 재사용 거부, 발표 30일 전 파기 거부).
- 최소 수집: 응모 테이블에는 이메일 원문이 없다(정규화 이메일의 SHA-256 만 — 다계정 차단용). 이메일은 auth.users 에서 필요할 때만 읽는다. 지갑 주소·실명은 당첨자만.
- 관리자: `auth.users.raw_app_meta_data.role = 'admin'` (서비스 롤만 설정 가능). 관리자도 브라우저에서 테이블을 직접 못 읽고 `ev_stats`(응모 수·국가 분포·일별·마케팅 동의 수·당첨자 마스킹) 만 받는다. **원문(당첨자 주소·실명)은 Supabase 대시보드 Table Editor 에서만** 본다.
- 관리자 화면(Artifact 시안): 개인정보 원문 없음 — 응모자 수, 국가 분포, 일별 응모, 추첨 버튼(시드 입력), 당첨자 마스킹, 파기 버튼. 지금은 더미 숫자 + "실데이터 연결 예정". 실데이터 연결은 관리자 로그인 후 `ev_stats` 호출(아티팩트 capabilities 로 Supabase 키 없이 연결하는 방법은 연결 시점에 결정).

## 4. 응모 개인정보 수집·이용 동의 문구 (버전 ev-2026-11-02)

- 목적: 추첨, 당첨 안내, 부정 응모 확인
- 항목: 회원 이메일(가입 정보에서 확인, 따로 받지 않음), 거주 국가, 응모 일시 · 당첨자만: 받을 코인·네트워크·지갑 주소·받는 거래소·수령인 실명
- 보유 기간: 응모 정보는 당첨자 발표 후 30일 뒤 파기. 당첨자 수령 정보는 경품 지급 후 30일 뒤 파기(지급 증빙인 전송 해시·수량·일자만 보관)
- 제3자 제공: 없음
- 거부 권리: 동의하지 않을 수 있으며, 이 경우 응모할 수 없지만 서비스 이용에는 제한이 없음
- (별도, 선택) 마케팅 정보 수신: 이메일 / 카카오톡 — 응모·당첨과 무관, 언제든 철회

## 5. 부정 응모 방지

1. 회원(사이트 가입 + 필수 동의) + 이메일 인증 완료 계정만 (`email_confirmed_at`).
2. 회차당 1계정 1회(`unique(event_id,user_id)`) + 1인 1회: gmail 점·+태그를 정규화한 이메일 해시 중복 차단.
3. 일회용 메일 도메인 차단(목록은 `ev_private.disposable` 에 추가).
4. 지갑 주소: 다른 계정이 쓴 주소면 수령 신청 거부(주소 해시로 파기 후에도 차단 유지).
5. 90일 내 재당첨 제외, 운영자·가족 제외.
6. 당첨 확인 절차: 로그인한 당첨자 본인만 14일 안에 수령 신청 → 세준이 대시보드에서 같은 국가·같은 시각대 몰림, 비슷한 이메일 패턴을 한 번 보고 지급. 의심되면 `ev_entries.disqualified` 에 사유 기록 후 해당 당첨 'rejected'.
7. (켜기 전 권장) Cloudflare Turnstile — 인증 에이전트 로그인 폼에 붙이면 응모도 함께 보호.
